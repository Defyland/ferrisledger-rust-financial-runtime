# Benchmark Results: 2026-05-30 Smoke Baseline

## Machine and runtime

- Machine: local Apple Silicon workstation
- Rust: `rustc 1.95.0`
- API mode: `target/release/ferrisledger serve --bind 127.0.0.1:18080 --store-path /tmp/ferrisledger-k6-events.jsonl --api-key dev-secret --rate-limit-per-minute 1000`
- Store: local JSONL file under `/tmp/ferrisledger-k6-events.jsonl`

## Criterion replay benchmark

Command:

```bash
cargo bench -p ferrisledger-runtime --bench replay -- --sample-size 10
```

Scenario:

- Seed one account stream.
- Append 100 deposit events.
- Replay the stream into an account snapshot.

Result:

| Benchmark | p50/estimate range |
| --- | --- |
| `replay_100_deposits` | 239.92 us to 439.14 us, mean 320.18 us |

## k6 smoke benchmark

Command:

```bash
BASE_URL=http://127.0.0.1:18080 API_KEY=dev-secret k6 run benchmarks/k6-smoke.js
```

- 1 VU

- Each iteration opens one account and deposits once

## Notes

The smoke result is intentionally small. It confirms the API path, request ID
and correlation ID response headers, store append, and idempotency-ready command
flow are healthy before longer load/stress/spike runs. The current bottleneck
remains JSONL append plus fsync. CPU and memory were not separately sampled in
this smoke run; that is acceptable for smoke but required for the next
load/stress evidence pass.
